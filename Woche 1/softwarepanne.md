Der Standish Report stellt hierzu regelmäßig die Ergebnisse von Untersuchungen vor. In der Vorlesung wurden verschiedene Beispiele erläutert, bei denen ein Softwarefehler oder eine Panne im Entwicklungsprozess zu Problemen geführt hat.

Softwarefehler bei Knight Capital (2012)

Einsatzbereich und Ablauf

Knight Capital war ein US-amerikanisches Finanzunternehmen, das automatisierten Wertpapierhandel betrieb. Die Software SMARS verarbeitete und leitete Börsenaufträge weiter.

Am 1. August 2012 führte ein Fehler nach einem Softwareupdate dazu, dass das System innerhalb von etwa 45 Minuten Millionen unerwünschter Börsenaufträge ausführte. Betroffen waren 154 Aktien. Knight Capital erlitt dadurch einen Verlust von rund 460 Millionen US-Dollar. Auch die Kurse einzelner Aktien wurden zeitweise beeinflusst.

Ursache

Bei der Aktualisierung wurde die neue Software nur auf sieben von acht Servern installiert. Auf dem achten Server blieb eine alte Programmversion mit der Funktion „Power Peg“ erhalten. Durch die neue Software wurde diese Funktion unbeabsichtigt aktiviert, wodurch das System immer wieder neue Handelsaufträge erzeugte.

Zusätzlich fehlten ausreichende Kontrollen, um unterschiedliche Softwareversionen auf den Servern zu erkennen. Vorhandene Warnmeldungen wurden nicht rechtzeitig als kritisches Problem behandelt. (SEC, 2013)

Folgen und mögliche Vermeidung

Neben dem Verlust von rund 460 Millionen US-Dollar wurde das Vertrauen in das Unternehmen beschädigt. 2013 verhängte die US-Börsenaufsicht SEC außerdem eine Geldstrafe von zwölf Millionen US-Dollar wegen unzureichender Kontrollen und Risikoverfahren.

Der Fehler hätte durch eine vollständige und überprüfte Installation auf allen Servern vermieden werden können. Außerdem hätte die veraltete Funktion entfernt, das System unter realistischen Bedingungen getestet und eine automatische Abschaltung bei ungewöhnlich vielen Handelsaufträgen eingerichtet werden müssen. Auch eine schnellere Reaktion auf Warnmeldungen hätte den Schaden begrenzen können.

Fazit

Der Vorfall zeigt, dass nicht nur die Programmierung, sondern auch Updates, Tests und Überwachung entscheidend für die Zuverlässigkeit einer Software sind. Eine unvollständige Installation und fehlende Sicherheitskontrollen können selbst bei einem etablierten Unternehmen zu enormen Schäden führen.
